# 아이디어 만들기

> 상태: 초안

## 이번 장에서 할 일

아이디어를 넓게 만든 뒤 묶고, 평가하고, 실행 가능한 후보로 발전시킵니다.

## 아이디어와 결정은 분리하세요

처음부터 “가장 좋은 아이디어 하나”를 요구하면 익숙한 답으로 빨리 좁혀질 수 있습니다. 먼저 가능성을 넓히고, 다음 대화에서 기준을 적용합니다.

```text
아이디어 넓히기 → 비슷한 것 묶기 → 평가 기준 정하기 → 후보 비교하기 → 사람이 선택하기
```

## 준비물

- 해결하려는 문제
- 대상과 상황
- 예산, 시간, 인원 같은 현실 조건
- 반드시 피할 것
- 나중에 사용할 평가 기준

## 먼저 해보기

```text
팀원 12명이 참여하는 30분짜리 온라인 회고 방법을 12개 제안해줘.
별도 유료 도구 없이 할 수 있어야 하고, 말이 적은 사람도 참여하기 쉬워야 해.
지금은 평가하거나 순위를 매기지 말고 가능한 한 서로 다른 방향으로 제안해줘.
```

## 결과가 아쉽다면

### 다양성 늘리기

```text
비슷한 아이디어를 묶고, 비어 있는 방향을 찾아 새로운 아이디어를 5개 더 제안해줘.
```

### 관점 바꾸기

```text
진행자, 처음 참여하는 사람, 말이 적은 사람의 관점에서 각각 불편한 점을 찾아 개선 아이디어를 내줘.
```

### 평가 기준 만들기

```text
이 아이디어를 참여 장벽, 준비 시간, 진행 난이도, 결과의 유용성으로 평가하려고 해.
각 기준을 어떻게 판단할지 정의해줘. 아직 점수는 매기지 마.
```

### 후보 발전시키기

```text
내가 3번 아이디어를 선택했어.
30분 진행 순서, 준비물, 진행자 멘트, 예상 문제와 대응을 구체화해줘.
```

## 좋은 질문을 만드는 브레인스토밍

아이디어 자체보다 먼저 질문을 만들 수도 있습니다.

```text
신규 고객의 첫 사용 경험을 개선하려고 해.
해결책을 제안하기 전에 우리가 조사해야 할 질문을 고객, 제품, 운영, 데이터의 관점으로 나눠 작성해줘.
```

문제를 충분히 이해하지 못했다면 해결책을 빨리 만드는 것보다 질문을 넓히는 편이 낫습니다.

## 반대 관점 사용하기

```text
이 아이디어가 실패했다고 가정해줘.
실패 원인을 예산, 참여, 일정, 운영의 관점에서 찾고 예방책을 제안해줘.
```

```text
이 아이디어에 반대하는 팀원이 제기할 수 있는 가장 강한 우려 5개를 만들어줘.
```

## 어디까지 믿어야 할까요?

- 익숙한 아이디어를 새것처럼 표현할 수 있습니다.
- 실제 예산, 일정, 규정, 기술 가능성을 자동으로 알지 못합니다.
- 많은 아이디어가 좋은 아이디어를 뜻하지는 않습니다.
- 최종 선택에는 조직 목표와 현장 경험이 필요합니다.
- 다른 사람의 아이디어나 저작물을 그대로 사용하지 않았는지 확인합니다.

## 직접 해보기

### 과제

내 업무의 작은 문제 하나를 고릅니다.

1. 서로 다른 아이디어 10개 만들기
2. 비슷한 아이디어 묶기
3. 평가 기준 3개 정의하기
4. 후보 3개 비교하기
5. 후보 1개를 실행 계획으로 발전시키기

### 완료 체크

- [ ] 아이디어 생성과 평가를 분리했다.
- [ ] 현실 조건을 제공했다.
- [ ] 서로 다른 관점을 사용했다.
- [ ] 최종 선택은 내가 근거와 함께 내렸다.
