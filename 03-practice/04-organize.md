# 정보 정리하기

> 상태: 초안

## 이번 장에서 할 일

뒤섞인 메모와 의견을 같은 기준으로 분류하고, 찾기 쉬운 목록이나 표로 바꿉니다.

## 이럴 때 써보세요

- 회의 메모의 주제가 뒤섞였을 때
- 고객 의견을 유형별로 묶을 때
- 여러 사람이 보낸 요청을 하나의 목록으로 합칠 때
- 문서에서 이름, 날짜, 할 일 같은 항목을 뽑을 때

## 준비물

- 정리할 원문
- 분류 기준 또는 원하는 최종 용도
- 중복을 처리하는 방법
- 애매한 항목을 처리하는 방법

개인정보와 기밀정보는 입력 전에 제거하거나 가명으로 바꿉니다.

## 먼저 해보기

```text
아래 메모를 일정, 예산, 담당자, 위험, 미결정 사항으로 분류해줘.
원문의 표현은 가능한 한 유지하고, 어느 범주인지 애매한 항목은 “분류 확인 필요”로 따로 모아줘.
```

## 분류 기준이 없을 때

바로 정리하게 하지 말고 기준부터 제안받을 수 있습니다.

```text
아래 고객 의견을 읽고 업무에 도움이 될 분류 기준을 2가지 제안해줘.
각 기준의 장단점을 설명하고, 아직 실제 분류는 하지 마.
```

기준을 고른 뒤 실행합니다.

```text
두 번째 기준으로 분류해줘. 하나의 의견이 여러 범주에 해당하면 중복 표시해줘.
```

## 결과가 아쉽다면

### 원문 추적 가능하게 만들기

```text
각 항목에 원문 번호를 붙여줘. 어떤 메모에서 나온 내용인지 나중에 확인할 수 있게 해줘.
```

### 중복 처리 정하기

```text
같은 요청은 하나로 합치되, 언급된 횟수와 원문 번호를 남겨줘.
표현은 비슷하지만 의미가 다른 내용은 합치지 마.
```

### 사실과 제안 분리하기

```text
확정된 사실, 누군가의 의견, 앞으로의 제안을 구분해줘.
```

### 표로 바꾸기

```text
결과를 항목 / 분류 / 원문 근거 / 담당자 / 기한 / 상태의 표로 만들어줘.
없는 정보는 추측하지 말고 “확인 필요”로 표시해줘.
```

## 한 단계 더 해보기

정리한 결과에서 다음 행동을 만듭니다.

```text
정리된 미결정 사항을 의사결정 질문으로 바꾸고, 각 질문에 답해야 할 사람과 필요한 자료를 제안해줘.
제안한 담당자는 확정하지 말고 “제안”이라고 표시해줘.
```

## 어디까지 믿어야 할까요?

- 비슷해 보이는 항목을 잘못 합치지 않았는지 원문과 확인합니다.
- 분류 과정에서 원문의 의미가 단순화되지 않았는지 봅니다.
- 담당자와 기한을 새로 지어내지 않았는지 확인합니다.
- 빈도만으로 중요도를 판단하지 않습니다.

## 직접 해보기

### 과제

뒤섞인 메모 10개 이상을 준비합니다. 분류 기준을 먼저 정한 뒤 표로 만들고, 애매한 항목과 누락된 정보를 따로 정리하세요.

### 완료 체크

- [ ] 분류의 목적과 기준을 정했다.
- [ ] 애매한 항목의 처리 방법을 말했다.
- [ ] 결과를 원문까지 추적할 수 있다.
- [ ] 중복과 누락을 직접 확인했다.
