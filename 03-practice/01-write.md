# 글 작성하기

> 상태: 초안

## 이번 장에서 할 일

빈 화면에서 시작하지 않고, 독자·목적·핵심 메시지가 분명한 업무 글의 초안을 만듭니다.

## 이럴 때 써보세요

- 이메일이나 공지의 첫 문장이 떠오르지 않을 때
- 메모를 보고서나 기획안의 구조로 바꿀 때
- 같은 내용을 여러 독자에게 맞춰 써야 할 때
- 초안을 빠르게 만든 뒤 내가 검토하고 고칠 수 있을 때

최종 입장과 책임이 중요한 글은 사람이 승인해야 합니다. ChatGPT에는 초안과 선택지를 맡깁니다.

## 준비물

글을 쓰기 전에 다음 다섯 가지를 짧게 적습니다.

| 항목 | 예시 |
|---|---|
| 만들 것 | 팀 공지 |
| 독자 | 프로젝트 팀원 8명 |
| 목적 | 변경된 마감일과 이유 알리기 |
| 핵심 사실 | 마감일이 10월 20일에서 22일로 변경 |
| 기대 행동 | 새 일정 확인 후 오늘 안에 답장 |

## 먼저 해보기

```text
프로젝트 팀원에게 보낼 일정 변경 공지를 작성해줘.
마감일이 10월 20일에서 22일로 바뀌었고, 팀원들이 새 일정을 확인한 뒤 오늘 안에 답장하도록 해줘.
```

## 결과가 아쉽다면

### 독자와 사용처 정하기

```text
이 글은 사내 메신저에 올릴 거야. 모바일에서 빠르게 읽히도록 첫 줄에 결론을 써줘.
```

### 말투 조정하기

```text
명령처럼 들리지 않게 하되, 확인 요청은 분명하게 유지해줘.
```

### 포함할 사실과 금지할 추측 정하기

```text
변경 이유는 외부 검토가 늦어졌기 때문이야.
누구의 잘못인지 추측하거나 책임을 단정하지 마.
```

### 여러 방향 비교하기

```text
첫 문장만 정중한 버전, 간결한 버전, 친근한 버전으로 하나씩 제안해줘.
```

## 한 단계 더 해보기

한 초안을 여러 산출물로 바꿉니다.

```text
이 공지를 바탕으로 다음 두 가지를 만들어줘.
1. 팀장에게 보고할 3문장 요약
2. 일정표에 붙일 한 줄 메모
세 결과의 날짜와 변경 이유는 같아야 해.
```

## 어디까지 믿어야 할까요?

- 이름, 날짜, 수치, 링크는 원자료와 대조합니다.
- 제공하지 않은 사실이 추가되지 않았는지 확인합니다.
- 조직의 공식 입장과 말투에 맞는지 검토합니다.
- 고객이나 외부에 보내기 전 담당자가 최종 승인합니다.
- 민감정보가 있다면 입력 전에 삭제하거나 가명으로 바꿉니다.

## 직접 해보기

### 과제

오늘 보낼 업무 글 하나를 고릅니다. 먼저 `누구에게 / 왜 / 핵심 사실 / 기대 행동`을 적고 초안을 요청하세요. 그다음 말투나 길이를 한 번 수정하고, 사실을 한 번 검증합니다.

### 완료 체크

- [ ] 독자와 목적을 설명했다.
- [ ] 반드시 포함할 사실을 제공했다.
- [ ] 독자가 해야 할 행동을 분명히 했다.
- [ ] 한 번 이상 후속 요청으로 고쳤다.
- [ ] 발송 전에 이름·날짜·수치를 직접 확인했다.
