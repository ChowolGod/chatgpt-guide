# 자동화의 기본 개념

> 상태: 초안

## 이번 장에서 할 일

반복 업무를 시작 조건, 입력, 처리, 검토, 출력으로 나누고 어떤 부분을 자동화해도 되는지 판단합니다.

## 자동화는 무엇일까요?

자동화는 정해진 조건이 생겼을 때 정해진 절차를 반복하게 만드는 것입니다.

```text
시작 조건 → 입력 수집 → 처리 → 검토 또는 승인 → 결과 전달 → 기록
```

예를 들어 “매주 월요일 아침 지난주 자료를 모아 보고서 초안을 만들고, 담당자에게 검토를 요청한다”는 하나의 자동화 흐름입니다.

자동화의 목표는 사람이 아무것도 하지 않는 상태가 아닙니다. 반복 작업은 줄이고 중요한 판단에는 사람의 시간을 쓰는 것이 목표입니다.

## 자동화 전에 수동으로 안정화하세요

다음 순서로 범위를 넓히는 것이 안전합니다.

1. 한 번의 좋은 요청으로 실행한다.
2. 입력 양식과 검토 체크리스트를 만든다.
3. 여러 사례에서 같은 절차가 통하는지 시험한다.
4. 정해진 시각에 초안을 만드는 단계만 자동화한다.
5. 충분히 검증된 낮은 위험의 행동만 연결한다.

수동으로도 자주 실패하는 업무를 자동화하면 실패가 더 빨리 반복됩니다.

## 자동화의 여섯 요소

### 1. 시작 조건

언제 실행할지 정합니다.

- 매주 월요일 오전 9시
- 새 설문 응답이 50개 쌓였을 때
- 담당자가 “검토 준비” 상태로 바꿨을 때

시간대, 공휴일, 중복 실행 조건도 확인합니다.

### 2. 입력

어떤 자료를 어디서 가져올지 정합니다. 파일명만 쓰지 말고 폴더, 기간, 필수 열과 최신 버전 기준을 적습니다.

### 3. 처리

요약, 분류, 계산, 초안 작성처럼 실제로 반복할 단계를 순서대로 적습니다.

### 4. 검토와 승인

숫자, 개인정보, 외부 공개, 비용 발생처럼 사람이 반드시 확인할 지점을 정합니다.

### 5. 출력과 알림

결과의 형식, 저장 위치, 받을 사람을 정합니다. 변화가 없을 때도 매번 알릴지, 의미 있는 변화나 실패가 있을 때만 알릴지도 정합니다.

### 6. 기록과 복구

언제 실행됐고 어떤 자료를 사용했으며 무엇이 실패했는지 남깁니다. 잘못된 결과를 취소하거나 이전 버전으로 돌아가는 방법도 필요합니다.

## 자동화하기 좋은 일

- 입력 형식과 절차가 비교적 일정하다.
- 성공과 실패를 구분할 기준이 있다.
- 결과를 사람이 검토한 뒤 사용할 수 있다.
- 실패해도 피해가 작고 되돌릴 수 있다.
- 사용 자료와 접근 권한이 명확하다.

## 아직 자동화하지 않는 편이 좋은 일

- 규칙보다 예외가 더 많다.
- 작은 실수도 법적·금전적·안전상 피해가 크다.
- 승인 없이 고객이나 외부에 메시지를 보내야 한다.
- 사람의 감정과 복잡한 맥락을 판단해야 한다.
- 성공 여부를 확인할 방법이 없다.
- 입력 자료의 위치와 형식이 매번 달라진다.

이런 업무도 자료 수집이나 초안 작성처럼 위험이 낮은 일부 단계는 자동화할 수 있습니다.

## 실전 설계: 주간 현황 초안

```text
[시작 조건]
매주 월요일 오전 9시, 한국 시간

[입력]
지난 월요일부터 일요일까지의 승인된 업무 기록

[처리]
완료, 진행 중, 위험, 다음 행동으로 분류

[출력]
500자 이내의 팀 공유용 초안과 확인 필요 목록

[검토]
담당자가 날짜, 수치, 이름과 공개 범위를 확인

[행동 제한]
초안만 만들고 자동 발송하지 않음

[알림]
초안이 준비됐거나 입력 누락으로 실패했을 때 담당자에게 알림

[기록]
실행 시각, 사용한 자료 기간, 누락 항목을 기록
```

## 자동화 요청 예시

```text
매주 월요일 오전 9시에 지난주 업무 기록을 바탕으로
주간 현황 보고 초안을 준비해줘.
완료, 진행 중, 위험, 다음 행동 순서로 500자 이내로 작성하고,
날짜·수치·담당자가 불명확하면 추측하지 말고 확인 목록에 넣어줘.
초안은 발송하지 말고 내가 검토할 수 있게 알려줘.
입력 자료가 없으면 보고서를 만들지 말고 누락 사실만 알려줘.
```

예약 실행 기능의 이름과 제공 여부는 제품, 요금제, 조직 설정에 따라 달라질 수 있습니다. 기능이 없다면 캘린더 알림과 저장된 템플릿을 조합해 같은 절차를 반자동으로 운영할 수 있습니다.

## 첫 한 달은 관찰 기간으로 두세요

자동화를 켠 뒤에는 다음을 기록합니다.

- 정상 실행 횟수와 실패 횟수
- 사람이 고친 항목과 반복되는 오류
- 불필요한 알림과 놓친 알림
- 예상하지 못한 입력과 예외
- 실제로 줄어든 시간

오류가 반복되면 자동화 범위를 줄이고 입력 양식이나 중단 조건부터 수정합니다.

## 실행 전 안전 점검

- [ ] 수동 절차를 여러 번 성공시켰는가?
- [ ] 입력 자료와 접근 권한이 명확한가?
- [ ] 중복 실행을 막을 방법이 있는가?
- [ ] 중요한 행동 전에 사람이 승인하는가?
- [ ] 실패와 누락을 알아차릴 수 있는가?
- [ ] 잘못된 변경을 되돌릴 수 있는가?
- [ ] 실행 기록과 담당자가 정해져 있는가?
- [ ] 더 이상 필요 없을 때 끄는 방법을 아는가?

## 어디까지 믿어야 할까요?

자동 실행은 자동 검증을 뜻하지 않습니다. 원본 데이터 오류, 권한 만료, 변경된 웹페이지, 잘못된 시간대 때문에 결과가 달라질 수 있습니다. 정기적으로 표본을 원문과 대조하고, 중요한 외부 행동은 계속 사람의 승인 아래 두세요.

### 완료 체크

- [ ] 시작 조건, 입력, 처리, 검토, 출력, 기록을 적었다.
- [ ] 자동화하기 좋은 일인지 판단했다.
- [ ] 외부 발송이나 변경 전에 승인 지점을 두었다.
- [ ] 실패·누락·중복 실행 처리 방법을 정했다.
- [ ] 끄는 방법과 복구 방법을 확인했다.
- [ ] 시험 결과를 바탕으로 범위를 조정했다.
