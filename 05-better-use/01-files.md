# 파일 활용

> 상태: 초안

## 이번 장에서 할 일

문서·PDF·표·발표자료·이미지 파일을 목적에 맞게 제공하고, 원문을 근거로 한 결과를 만든 뒤 누락 여부를 확인합니다.

## 이럴 때 써보세요

- 긴 보고서의 핵심을 빠르게 파악할 때
- 여러 계약안이나 제안서를 같은 기준으로 비교할 때
- 표에서 이상한 값이나 반복되는 패턴을 찾을 때
- 기존 자료를 바탕으로 보고서나 발표자료 초안을 만들 때
- 문서의 표현, 구조, 오탈자를 점검할 때

파일을 열어 읽기만 하면 되는 일이나, 기밀 자료를 외부 서비스에 올릴 수 없는 상황에서는 먼저 조직의 규정을 확인하세요.

## 파일을 올리기 전에 확인할 것

### 1. 맞는 파일인가

- 최종본과 이전 버전을 구분했는가?
- 파일명만 다른 중복본은 없는가?
- 비교할 파일의 작성일과 기준 시점이 같은가?

### 2. 필요한 내용이 들어 있는가

- 스캔된 페이지가 빠지지 않았는가?
- 표가 이미지로만 들어 있지는 않은가?
- 암호가 걸려 있거나 열리지 않는 파일은 없는가?
- 여러 시트나 부록 가운데 분석할 범위를 알고 있는가?

### 3. 올려도 되는 자료인가

개인정보, 고객 정보, 미공개 실적, 계약 조건, 비밀번호와 인증 정보가 있는지 확인합니다. 필요하면 이름을 가리고, 일부 행만 남긴 예제 파일을 만들어 사용합니다.

## 요청은 세 부분으로 나누세요

```text
[자료]
첨부한 2026년 상반기 고객 의견 파일을 사용해줘.

[목적과 범위]
'의견' 시트의 1월부터 6월 데이터만 보고,
고객이 반복해서 말한 불편을 찾고 싶어.

[결과와 검증]
주제별 빈도, 대표 사례, 개선 아이디어를 표로 정리해줘.
각 결론 옆에 근거가 있는 행 번호를 적고,
읽지 못한 부분이나 확실하지 않은 해석은 따로 표시해줘.
```

파일을 첨부했다는 사실만으로 목적이 전달되지는 않습니다. **어느 파일의 어느 범위를, 무엇을 위해, 어떤 형태로 바꿀지**를 말하세요.

## 먼저 파일 지도를 만들어보세요

복잡한 파일은 곧바로 분석시키지 말고 구조부터 확인합니다.

```text
아직 분석하지 말고 먼저 이 파일의 구조를 알려줘.
문서라면 장과 부록, 표라면 시트 이름과 주요 열,
발표자료라면 슬라이드별 주제를 정리해줘.
읽을 수 없거나 비어 있는 부분도 표시해줘.
```

파일 지도가 맞는지 확인한 뒤 본 작업을 시작하면 엉뚱한 시트나 오래된 부록을 분석하는 일을 줄일 수 있습니다.

## 결과가 아쉽다면

### 근거 위치를 요청하세요

```text
중요한 결론마다 원문 페이지, 표의 행, 슬라이드 번호를 적어줘.
원문에 없는 내용은 '추론'이라고 표시해줘.
```

근거 위치는 검토 속도를 높이지만, 표시된 위치와 실제 내용이 일치하는지는 사람이 다시 확인해야 합니다.

### 여러 파일의 역할을 정하세요

```text
A 파일은 최신 정책의 기준 문서이고,
B 파일은 작년 실행 사례야.
A와 충돌하면 A를 우선해줘.
두 파일의 차이는 별도 표로 정리해줘.
```

### 원하는 결과물을 구체적으로 말하세요

“정리해줘” 대신 독자, 용도, 길이, 형식을 지정합니다.

```text
이 자료를 처음 보는 팀장을 위한 1쪽 보고서 초안으로 바꿔줘.
결론, 핵심 근거 3개, 위험 요인, 다음 행동 순서로 작성해줘.
```

## 파일로 결과를 받았다면

생성된 문서나 표는 다운로드했다는 이유로 완성된 것이 아닙니다.

- 문서: 제목, 본문, 표, 각주와 잘린 문장을 확인합니다.
- 스프레드시트: 모든 시트, 수식, 단위, 날짜 형식을 확인합니다.
- 발표자료: 모든 슬라이드의 글자 넘침, 이미지, 출처를 확인합니다.
- PDF: 모든 페이지가 열리고 글꼴과 표가 깨지지 않았는지 확인합니다.

```text
완성 파일을 원본과 다시 대조해줘.
누락된 항목, 바뀐 숫자, 근거 없는 문장을 목록으로 알려줘.
```

이 요청도 보조 검토일 뿐입니다. 중요한 숫자와 고유명사는 직접 원문과 대조하세요.

## 어디까지 믿어야 할까요?

ChatGPT가 파일을 읽었다고 해도 작은 글자, 복잡한 표, 스캔 품질이 낮은 페이지, 숨겨진 시트까지 완벽하게 해석했다고 볼 수 없습니다.

- 읽지 못한 부분을 명시하도록 요청합니다.
- 숫자, 이름, 날짜, 인용문은 원문과 대조합니다.
- “파일에 없다”와 “찾지 못했다”를 구분합니다.
- 민감정보 처리 규정과 보관 정책을 따릅니다.

## 직접 해보기

### 과제

실제 업무 파일 하나를 선택해 다음 순서로 처리해보세요.

1. 파일 구조를 먼저 확인한다.
2. 분석 범위와 목적을 지정한다.
3. 근거 위치가 포함된 결과를 요청한다.
4. 결과를 원문과 대조한다.
5. 다음 업무에 쓸 산출물로 바꾼다.

### 완료 체크

- [ ] 사용할 파일과 버전을 확인했다.
- [ ] 필요한 범위와 결과 형태를 지정했다.
- [ ] 읽지 못한 부분과 추론을 표시하게 했다.
- [ ] 중요한 숫자·이름·날짜를 원문과 대조했다.
- [ ] 생성된 파일의 모든 페이지·시트·슬라이드를 열어봤다.

## 기억할 한 문장

**파일을 첨부하는 것은 시작일 뿐이며, 범위와 목적과 근거 확인 방법까지 알려줘야 합니다.**
