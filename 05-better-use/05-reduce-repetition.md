# 반복 업무 줄이기

> 상태: 초안

## 이번 장에서 할 일

자주 되풀이되는 업무에서 고정 요소와 매번 바뀌는 요소를 분리해, 누구나 다시 사용할 수 있는 요청 템플릿과 체크리스트를 만듭니다.

## 먼저 반복 업무를 발견하세요

다음 질문 가운데 두 개 이상이 맞으면 템플릿을 만들 가치가 있습니다.

- 비슷한 일을 한 달에 두 번 이상 하는가?
- 시작할 때마다 지난 문서나 메시지를 찾아보는가?
- 결과의 항목과 순서가 거의 같은가?
- 사람마다 결과 품질이 크게 다른가?
- 빠뜨리기 쉬운 확인 항목이 있는가?

반복 횟수보다 실패 비용이 큰 일이라면 빈도가 낮아도 체크리스트가 유용합니다.

## 업무를 한 번 관찰해 기록하세요

```text
시작 자료 → 실제로 한 행동 → 중간 판단 → 최종 결과 → 검토
```

머릿속의 이상적인 절차보다 실제로 처리한 한 번의 과정을 적으세요. 어디서 자료를 찾느라 멈췄는지, 어떤 예외가 생겼는지도 기록합니다.

## 고정 요소와 변경 요소를 나누세요

주간 업무 보고를 예로 들면 다음과 같습니다.

| 고정 요소 | 매번 바뀌는 요소 |
|---|---|
| 독자: 팀장 | 보고 기간 |
| 목적: 진행 상황 공유 | 완료한 일 |
| 항목 순서 | 진행 중인 일 |
| 분량과 말투 | 문제와 필요한 지원 |
| 숫자 검토 규칙 | 다음 주 계획 |

고정 요소는 템플릿에 넣고, 변경 요소는 빈칸으로 남깁니다.

## 재사용 가능한 입력 양식

```text
[보고 기간]

[완료한 일]
- (내용 입력)

[진행 중인 일]
- (내용 입력)

[문제 또는 위험]
- (내용 입력)

[필요한 지원]
- (내용 입력)

[다음 주 계획]
- (내용 입력)
```

입력 양식은 프롬프트보다 먼저 중요합니다. 입력이 매번 제각각이면 결과도 안정되기 어렵습니다.

## 재사용 가능한 요청 템플릿

```text
아래 입력을 팀장에게 공유할 주간 업무 보고로 작성해줘.

[고정 규칙]
- 완료, 진행 중, 문제와 지원 요청, 다음 주 계획 순서
- 전체 500자 이내
- 업무명과 날짜는 입력에 있는 표현을 그대로 사용
- 모르는 담당자나 수치는 추측하지 않고 [확인 필요]로 표시
- 문제는 영향과 필요한 지원을 함께 작성

[이번 입력]
{{위 입력 양식 붙여넣기}}

[출력]
1. 공유용 보고서
2. 사실 확인이 필요한 항목 목록
```

## 예외와 중단 조건을 적으세요

잘 설계된 템플릿은 정상 상황뿐 아니라 멈춰야 할 상황도 알려줍니다.

```text
다음 경우에는 결과를 완성하지 말고 먼저 질문해줘.
- 보고 기간이 없음
- 전체 실적과 세부 수치가 서로 다름
- 담당자가 둘 이상인데 책임자가 구분되지 않음
- 고객 또는 직원의 민감정보가 포함됨
```

## 세 가지 사례로 시험하세요

1. **정상 사례:** 필요한 정보가 모두 있는 입력
2. **누락 사례:** 날짜나 수치 하나가 없는 입력
3. **예외 사례:** 서로 충돌하는 정보가 있는 입력

정상 사례만 통과한 템플릿은 아직 실무용이 아닙니다. 누락과 예외에서 추측하지 않고 멈추는지 확인하세요.

## 결과가 아쉽다면 템플릿을 고치세요

매번 긴 후속 요청을 한다면 그것은 다음 버전의 고정 규칙이 될 수 있습니다.

```text
변경 전: 문제를 정리해줘.
변경 후: 문제마다 영향, 원인, 필요한 지원을 한 줄씩 작성해줘.
```

템플릿 이름과 수정 날짜를 남기면 오래된 버전을 사용하는 실수를 줄일 수 있습니다.

```text
주간 업무 보고 템플릿 v1.2
수정일: 2026-09-10
변경: 수치 누락 시 [확인 필요] 표시 규칙 추가
```

## 무엇을 남겨야 할까요?

- 사용할 상황과 사용하지 않을 상황
- 필요한 입력 자료와 입력 양식
- 요청 템플릿
- 결과 예시 한 개
- 검토 체크리스트
- 예외와 중단 조건
- 담당자와 마지막 수정일

이 묶음이 있어야 다른 사람도 같은 품질로 다시 사용할 수 있습니다.

## 어디까지 믿어야 할까요?

템플릿은 판단을 대신하지 않습니다. 날짜, 수치, 담당자, 공개 범위처럼 매번 달라지는 값은 실행할 때마다 새로 확인해야 합니다. 규정이나 업무 방식이 바뀌면 템플릿도 함께 고쳐야 합니다.

## 기억할 한 문장

**반복 업무는 프롬프트 한 줄이 아니라 입력 양식, 처리 규칙, 예외, 검토표를 함께 남길 때 줄어듭니다.**
