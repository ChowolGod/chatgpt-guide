# ChatGPT도 틀릴 수 있다

> 상태: 초안

## 이번 장에서 할 일

그럴듯한 오류를 알아차리고, 결과의 위험도에 맞게 검증하는 습관을 만듭니다.

이 장을 마치면 답변에서 확인할 항목을 찾고 검증 방법을 정할 수 있습니다.

## 자연스러운 문장과 정확한 내용은 다릅니다

ChatGPT의 답변은 매끄럽고 자신감 있게 보일 수 있습니다. 하지만 표현이 자연스럽다는 사실은 내용이 맞다는 증거가 아닙니다.

다음과 같은 오류가 생길 수 있습니다.

- 실제와 다른 사실을 말한다.
- 이름, 날짜, 수치, 단위를 틀린다.
- 원문에서 중요한 조건이나 예외를 빠뜨린다.
- 없는 출처나 찾지 못한 내용을 제시한다.
- 자료에 없는 원인과 의도를 추측한다.
- 서로 다른 기준의 수치를 같은 것처럼 비교한다.

이런 오류는 너무 그럴듯해서 지나치기 쉽습니다. 그래서 “틀릴 수 있다”는 경고만 기억하기보다 **무엇을 어떻게 확인할지** 정해야 합니다.

## 결과의 위험도부터 판단하기

모든 답변을 같은 수준으로 검증할 필요는 없습니다. 틀렸을 때 생길 영향을 기준으로 나눕니다.

| 위험도 | 예시 | 권장 행동 |
|---|---|---|
| 낮음 | 브레인스토밍, 개인용 초안, 제목 후보 | 빠르게 읽고 목적에 맞게 수정 |
| 보통 | 팀 공지, 회의록, 내부 보고서 | 원자료와 핵심 사실 대조 후 사용 |
| 높음 | 고객 발송, 공개 자료, 주요 수치 분석 | 담당자 검토와 출처 확인 후 사용 |
| 매우 높음 | 법률·의료·재무·안전·인사 결정 | 자격 있는 전문가와 책임자 검토 필수 |

위험도가 높을수록 ChatGPT의 답변을 “결론”이 아니라 “검토할 초안”으로 다룹니다.

## 가장 먼저 확인할 다섯 가지

### 1. 숫자

합계, 평균, 비율, 증감률, 단위, 기간을 확인합니다.

```text
표에 사용한 계산식을 항목별로 보여줘.
원본 값, 계산 과정, 결과를 구분해줘.
```

가능하면 원본 데이터나 계산기로 다시 계산합니다.

### 2. 이름과 날짜

사람 이름, 회사명, 제품명, 행사 날짜, 마감일은 원문과 대조합니다. 한 글자 차이도 실제 업무에서는 문제가 될 수 있습니다.

### 3. 인용과 출처

링크가 존재하는지만 보지 말고, 링크의 내용이 주장과 실제로 일치하는지 확인합니다.

```text
각 핵심 주장 옆에 원출처를 붙여줘.
출처에서 직접 확인되지 않는 해석은 “해석”이라고 표시해줘.
```

### 4. 누락

요약에는 반드시 무언가가 빠집니다. 무엇을 남겨야 하는지 먼저 정하고 원문과 비교합니다.

```text
요약에서 빠진 중요한 조건, 예외, 반대 의견이 있는지 원문과 대조해줘.
```

### 5. 가정

자료에 없는 내용을 무엇으로 가정했는지 묻습니다.

```text
이 결과를 만들 때 사용한 가정을 목록으로 적어줘.
자료로 확인한 사실과 네가 추정한 내용을 구분해줘.
```

## 검증을 돕는 요청

다음 문장은 여러 업무에 반복해서 사용할 수 있습니다.

```text
이 결과에서 틀렸을 때 영향이 큰 숫자, 이름, 날짜, 인용, 주장을 찾아 체크리스트로 만들어줘.
```

```text
사용한 출처와 접근하지 못한 자료를 구분해줘. 확인하지 못한 내용은 명확히 표시해줘.
```

```text
원문에 직접 있는 내용, 원문을 바탕으로 한 해석, 자료에 없는 추정을 각각 구분해줘.
```

```text
이 결론에 반대하는 검토자라면 어떤 약점과 누락을 지적할지 알려줘.
```

검증 요청을 했다고 결과가 자동으로 참이 되는 것은 아닙니다. ChatGPT가 자기 답변을 다시 검토하는 것은 유용한 1차 점검이지만, 중요한 사실은 원자료나 독립된 신뢰할 만한 출처로 확인합니다.

## 예제로 오류 찾기

다음은 가상의 주간 보고서 초안입니다.

```text
이번 주 신규 고객은 120명으로 지난주보다 25% 증가했습니다.
고객 만족도는 4.8점으로 업계 평균보다 높습니다.
따라서 신규 광고 캠페인이 성장의 주된 원인이라고 볼 수 있습니다.
다음 달에는 광고 예산을 두 배로 늘리는 것이 좋습니다.
```

문장은 자연스럽지만 그대로 사용해서는 안 됩니다.

| 문장 | 확인할 질문 |
|---|---|
| 신규 고객 120명 | 원본 데이터에서 같은 기간과 기준으로 집계했는가? |
| 25% 증가 | 지난주 값은 얼마이며 계산이 맞는가? |
| 만족도 4.8점 | 만점, 응답자 수, 조사 기간은 무엇인가? |
| 업계 평균보다 높음 | 비교한 업계 평균의 출처와 시점은 무엇인가? |
| 광고가 주된 원인 | 다른 원인을 배제할 근거가 있는가? |
| 예산을 두 배로 증액 | 비용, 수익, 위험을 검토했는가? 누가 결정하는가? |

하나의 짧은 문단에도 **사실, 비교, 원인 해석, 권고**가 섞여 있습니다. 각각 다른 방식으로 검증해야 합니다.

## 검증 절차: 표시하고, 대조하고, 승인받기

### 1단계: 표시하기

답변에서 숫자, 이름, 날짜, 인용, 중요한 주장을 표시합니다.

### 2단계: 대조하기

원본 파일, 공식 문서, 최신 원출처와 비교합니다. 찾지 못한 내용은 삭제하거나 “확인 필요”로 남깁니다.

### 3단계: 승인받기

외부 발송, 공개, 계약, 결제, 인사, 안전에 영향을 주는 결과는 적절한 담당자나 전문가가 검토한 뒤 사용합니다.

## 직접 해보기

### 과제

앞의 가상 주간 보고서에서 다음을 구분해 표시합니다.

- 사실 주장
- 비교
- 원인에 대한 해석
- 앞으로의 제안

그다음 각 항목에 필요한 원자료나 검토자를 적습니다.

마지막으로 아래 요청을 실행하고, 내가 만든 검증 목록과 비교해보세요.

```text
아래 보고서 초안에서 확인이 필요한 사실과 가정을 찾아줘.
각 항목을 “확인할 내용 / 필요한 근거 / 틀렸을 때 영향”의 표로 정리해줘.
근거가 없으면 결론을 확정하지 마.

[가상 주간 보고서 붙여넣기]
```

### 완료 체크

- [ ] 자연스러운 문장과 정확한 사실을 구분했다.
- [ ] 숫자·이름·날짜·출처·누락·가정을 확인했다.
- [ ] 위험도에 맞는 검증 방법을 정했다.
- [ ] 중요한 결과의 최종 검토자를 정했다.

## 기억할 한 문장

> 답변이 그럴듯할수록 확인을 건너뛰기 쉽습니다. 중요한 결과는 원자료와 출처로 검증한 뒤 사용합니다.
