# 데이터에서 보고서까지

> 상태: 초안

## 이번 장에서 할 일

데이터의 구조와 품질을 확인하고, 업무 질문에 맞는 계산·해석·검증을 거쳐 근거가 있는 보고서를 만듭니다.

```text
데이터 파일
→ 구조와 품질 점검
→ 분석 질문과 계산 방법 합의
→ 분석
→ 핵심 수치 재검증
→ 인사이트와 한계
→ 보고서와 차트
```

## 완성할 산출물

- 데이터 설명서와 품질 점검표
- 분석 질문과 계산 정의
- 핵심 결과와 재현 가능한 계산
- 사실·해석·제안이 구분된 인사이트
- 차트와 1쪽 보고서
- 한계와 추가로 필요한 데이터

## 예시 상황

1월부터 8월까지 고객 문의 데이터를 이용해 문의량이 급증한 채널과 원인 후보를 찾고, 다음 분기 상담 운영 계획을 제안해야 합니다.

## 준비물

- 원본 데이터 파일과 사본
- 행 하나와 각 열의 의미
- 기간, 단위, 필터 기준
- 개인정보 제거 또는 가명 처리
- 답하려는 업무 질문
- 결과를 검토할 데이터 담당자

원본은 보존하고 분석용 사본을 사용합니다.

## 1단계: 데이터 구조 확인하기

```text
첨부한 데이터를 바로 분석하지 말고 먼저 구조를 설명해줘.

확인할 것:
- 시트와 표의 이름
- 행 하나가 뜻하는 것
- 각 열의 의미와 데이터 형식
- 날짜 범위와 단위
- 총 행 수
- 빈값, 중복, 이상한 값
- 해석이 애매한 열

아직 데이터를 고치거나 결론을 내리지 마.
```

## 사람의 검토 1: 데이터 뜻 확인하기

- 문의 한 건이 행 하나인지 확인합니다.
- 생성일과 종료일 중 어떤 날짜를 분석할지 정합니다.
- 채널 이름이 기간 중 바뀌지 않았는지 봅니다.
- 테스트 데이터와 취소 건의 포함 여부를 정합니다.
- 개인정보가 분석에 필요하지 않다면 제거합니다.

## 2단계: 품질 문제와 처리안 만들기

```text
발견한 데이터 품질 문제를 문제 / 영향 / 처리 선택지 / 권장안 / 사람의 확인 필요 여부로 정리해줘.
원본 파일은 바꾸지 말고, 삭제나 보정이 필요한 행은 목록으로만 제안해줘.
```

빈값과 이상값을 임의로 없애면 결론이 달라질 수 있습니다. 처리 방법을 먼저 승인합니다.

## 3단계: 분석 질문과 지표 정의하기

```text
업무 질문은 “1월부터 8월까지 어느 채널의 문의량이 언제 급증했고, 운영 계획에서 무엇을 확인해야 하는가?”야.

이 질문에 답할 지표, 계산식, 기간 비교 방법을 제안해줘.
증가율의 분모가 0이거나 채널 분류가 바뀐 경우의 처리 방법도 알려줘.
아직 계산하지 마.
```

분석 전에 `문의량`, `급증`, `증가율`의 뜻을 합의합니다.

## 4단계: 분석 실행하기

```text
승인한 처리 방법과 지표로 분석해줘.
핵심 결과마다 원본 값, 계산식, 결과, 사용한 필터를 보여줘.
전체 결과뿐 아니라 채널별 결과를 비교하고, 이상값의 영향을 따로 알려줘.
```

## 5단계: 핵심 수치 재검증하기

```text
보고서에 사용할 핵심 수치 5개를 골라 재검증 표를 만들어줘.
열은 수치 / 원본 위치 / 계산식 / 첫 계산 결과 / 재계산 결과 / 일치 여부로 해줘.
불일치하면 원인을 찾기 전까지 보고서에 사용하지 마.
```

가능하면 다른 도구나 사람이 핵심 계산을 독립적으로 확인합니다.

## 6단계: 사실, 해석, 제안 구분하기

```text
분석 결과를 다음 세 부분으로 나눠줘.
1. 데이터에서 직접 확인된 사실
2. 사실을 바탕으로 한 해석과 가능한 원인
3. 다음 분기 운영을 위한 제안

가능한 원인을 실제 원인으로 단정하지 말고, 확인에 필요한 추가 데이터를 함께 적어줘.
```

문의 증가와 캠페인 시점이 겹쳐도 캠페인이 원인이라고 바로 결론 내릴 수는 없습니다.

## 7단계: 차트와 보고서 만들기

```text
검증된 결과를 부서장용 1쪽 보고서로 작성해줘.

순서:
1. 분석 질문과 사용 데이터
2. 핵심 결과 3개
3. 해석과 한계
4. 운영 제안 2개
5. 추가 확인이 필요한 질문

핵심 결과를 보여주는 차트 2개를 제안하고, 축·단위·기간·필터를 명시해줘.
모든 수치에 원본 위치와 계산 근거를 붙여줘.
```

## 사람의 검토 2: 보고서 판단 확인하기

- 차트 축과 단위가 오해를 만들지 않는가?
- 표본 수가 작은 그룹을 과도하게 해석하지 않았는가?
- 상관관계를 원인으로 단정하지 않았는가?
- 운영 제안이 실제 인력과 예산 안에서 가능한가?
- 다른 설명이나 반대 근거가 빠지지 않았는가?

## 8단계: 산출물 일치 확인하기

```text
분석표, 차트, 보고서를 서로 대조해줘.
기간, 필터, 단위, 합계, 증가율, 채널 이름이 다른 부분을 찾아 표로 보여줘.
보고서의 모든 주요 주장이 분석 결과로 뒷받침되는지도 확인해줘.
```

## 최종 확인 체크리스트

- [ ] 원본 파일을 보존했다.
- [ ] 행과 열의 의미, 기간, 단위를 확인했다.
- [ ] 빈값·중복·이상값 처리 방법을 승인했다.
- [ ] 분석 전에 질문과 계산식을 합의했다.
- [ ] 핵심 수치를 독립적으로 재검증했다.
- [ ] 사실, 해석, 제안을 구분했다.
- [ ] 차트와 보고서의 수치가 일치한다.
- [ ] 한계와 추가 데이터 필요성을 기록했다.

## PART 4 최종 점검

- [ ] 시작 자료와 최종 산출물을 정의할 수 있다.
- [ ] 큰 업무를 검토 가능한 중간 산출물로 나눌 수 있다.
- [ ] 사실 확인, 해석 승인, 외부 발송 같은 사람의 검토 지점을 정할 수 있다.
- [ ] 여러 산출물 사이의 수치·이름·결정을 대조할 수 있다.
- [ ] 결과를 반복 가능한 업무 흐름으로 기록할 수 있다.
