# 아이디어에서 최종 기획안까지

> 상태: 초안

## 이번 장에서 할 일

막연한 아이디어를 넓히고 평가한 뒤, 반대 관점의 검토를 거쳐 실행 가능한 기획안으로 만듭니다.

```text
문제 정의
→ 아이디어 확장
→ 평가 기준 합의
→ 후보 비교
→ 사람이 선택
→ 기획안 초안
→ 반대 관점 검토
→ 최종안
```

## 완성할 산출물

- 한 문장 문제 정의
- 아이디어 후보와 분류표
- 평가 기준과 후보 비교표
- 선택한 아이디어의 기획안
- 위험·반대 의견·미결정 사항
- 검토를 반영한 최종안

## 예시 상황

매주 30분 동안 팀 지식 공유 시간을 운영하고 싶습니다. 준비 부담이 낮고 말이 적은 팀원도 참여할 수 있어야 합니다.

## 준비물

- 해결할 문제와 현재 상황
- 대상 사용자 또는 참여자
- 예산, 시간, 인원, 도구 같은 제약
- 성공했다고 판단할 기준
- 결정권자와 실행 담당자

## 1단계: 문제부터 정의하기

```text
팀 지식 공유 시간을 기획하려고 해.
현재 문제는 좋은 정보가 개인에게 머물고, 정식 발표를 준비하는 부담 때문에 공유가 적다는 것이야.
대상은 12명의 팀원이고 매주 30분을 사용할 수 있어.

아직 해결책을 제안하지 말고, 문제 정의에서 모호하거나 빠진 내용을 질문해줘.
질문은 한 번에 5개 이내로 해줘.
```

좋은 기획은 아이디어보다 문제 정의에서 시작합니다.

## 사람의 검토 1: 문제와 성공 기준 합의하기

- 실제 문제가 준비 부담인지, 시간 부족인지, 심리적 안전감인지 확인합니다.
- 참여율, 공유 횟수, 재사용된 자료 수처럼 관찰 가능한 성공 기준을 정합니다.
- 해결 대상에 포함하지 않을 문제를 구분합니다.

## 2단계: 아이디어 넓히기

```text
다음 조건에서 서로 다른 운영 아이디어를 12개 제안해줘.
- 팀원 12명
- 매주 30분
- 유료 도구 추가 없음
- 발표 자료 준비는 10분 이내
- 말이 적은 사람도 참여 가능
지금은 순위를 매기지 말고 가능한 한 다양한 방향으로 제안해줘.
```

## 3단계: 아이디어 묶고 빈 방향 찾기

```text
12개 아이디어를 참여 방식과 준비 부담을 기준으로 묶어줘.
비슷한 아이디어는 차이를 설명하고, 아직 제안되지 않은 방향이 있으면 3개 추가해줘.
```

## 4단계: 평가 기준 정하기

```text
후보를 참여 장벽, 준비 시간, 운영 난이도, 학습 효과, 지속 가능성으로 평가하려고 해.
각 기준에서 “좋음 / 보통 / 우려”가 무엇을 뜻하는지 먼저 정의해줘.
아직 후보를 평가하지 마.
```

점수를 먼저 매기지 말고 기준의 뜻을 합의합니다.

## 5단계: 후보 비교하고 사람이 선택하기

```text
확정한 기준으로 후보를 비교해줘.
각 평가의 이유를 적고, 정보가 부족하면 “평가 보류”로 표시해줘.
마지막에 결정을 위해 확인해야 할 질문을 정리해줘.
```

ChatGPT의 추천을 그대로 선택하지 않습니다. 팀 분위기, 실행 의지, 다른 일정처럼 제공하지 않은 맥락을 사람이 반영합니다.

## 6단계: 기획안 초안 만들기

후보 하나를 고른 뒤 구체화합니다.

```text
우리는 “사례 한 장 공유” 방식을 선택했어.
다음 구조로 기획안 초안을 작성해줘.

1. 배경과 문제
2. 목표와 성공 기준
3. 참여 대상
4. 운영 방식과 30분 진행 순서
5. 준비물과 역할
6. 4주 시험 운영 일정
7. 예상 위험과 대응
8. 확인이 필요한 결정

확정된 내용과 네 제안을 구분해줘.
```

## 7단계: 반대 관점으로 검토하기

```text
이 기획에 반대하는 팀원, 진행자, 팀장의 관점에서 가장 강한 우려를 각각 3개씩 제시해줘.
각 우려가 실제로 일어날 가능성을 확인할 방법과 대응안을 제안해줘.
```

```text
시험 운영이 4주 뒤 실패했다고 가정해줘.
실패 원인을 참여, 준비 부담, 일정, 진행 방식, 결과 활용의 관점에서 분석해줘.
```

반대 의견을 없애려 하지 말고, 기획안에 반영하거나 미결정 사항으로 남깁니다.

## 사람의 검토 2: 실행 가능성 확인하기

- 실제 담당자가 역할을 수락했는가?
- 일정과 필요한 시간이 현실적인가?
- 기존 회의와 중복되지 않는가?
- 성공 지표를 수집할 수 있는가?
- 중단하거나 바꿀 기준이 있는가?

## 8단계: 최종안 만들기

```text
검토 의견 중 승인된 내용을 반영해 최종 기획안을 작성해줘.
변경된 부분, 반영하지 않은 의견과 이유, 아직 필요한 결정을 마지막에 기록해줘.
4주 시험 운영 뒤 계속 / 수정 / 중단을 판단할 기준도 포함해줘.
```

## 최종 확인 체크리스트

- [ ] 해결하려는 문제가 한 문장으로 분명하다.
- [ ] 아이디어 생성과 평가를 분리했다.
- [ ] 평가 기준의 뜻을 먼저 정의했다.
- [ ] 최종 선택은 사람이 근거와 함께 내렸다.
- [ ] 역할, 일정, 자원, 성공 기준이 있다.
- [ ] 반대 의견과 실패 가능성을 검토했다.
- [ ] 시험 운영 뒤 중단 또는 수정 기준이 있다.

## 내 업무에 적용하기

내 아이디어를 다음 한 문장으로 시작하세요.

```text
[대상]이 겪는 [문제]를 [제약 조건] 안에서 개선하고 싶다.
성공 여부는 [관찰 가능한 기준]으로 판단한다.
```

그다음 아이디어 확장, 기준 합의, 후보 비교, 사람의 선택, 기획안, 반대 검토의 순서를 따릅니다.

## 기억할 한 문장

> 아이디어를 바로 기획안으로 만들지 말고, 문제와 평가 기준을 합의한 뒤 사람의 선택과 반대 검토를 거치세요.
