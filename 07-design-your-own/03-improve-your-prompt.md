# 나만의 프롬프트 개선하기

> 상태: 초안

## 이번 장에서 할 일

실제 결과를 기준표로 평가하고 한 번에 한 요소씩 바꾸며, 무엇이 결과를 개선했는지 기록합니다.

## 느낌 대신 기준으로 평가하세요

“별로다”라고만 하면 무엇을 고쳐야 할지 알기 어렵습니다. 실행 전에 평가 기준과 통과 조건을 정하세요.

| 평가 항목 | 확인 질문 | 통과 기준 예시 |
|---|---|---|
| 정확성 | 원문과 다른 사실이 있는가? | 중요 오류 0건 |
| 완전성 | 필수 항목이 모두 있는가? | 5개 항목 모두 포함 |
| 적합성 | 독자와 목적에 맞는가? | 팀장이 다음 행동을 판단 가능 |
| 형식 | 길이와 구조가 맞는가? | 500자 이내, 순서 준수 |
| 안전성 | 추측·민감정보·무단 행동이 있는가? | 위험 항목 0건 |
| 효율 | 실제 시간이 줄었는가? | 기존보다 15분 이상 단축 |

## 첫 결과를 그대로 보관하세요

첫 버전을 지우지 말고 요청, 입력, 결과, 걸린 시간, 오류를 함께 남깁니다. 그래야 개선됐는지 비교할 수 있습니다.

```text
시험 날짜:
템플릿 버전:
사용한 입력:
걸린 시간:
평가 점수:
중요 오류:
사람이 수정한 내용:
```

## 실패를 원인별로 나누세요

| 보이는 문제 | 가능한 원인 | 먼저 고칠 곳 |
|---|---|---|
| 중요한 항목 누락 | 필수 항목이 불명확 | 결과 형태·체크리스트 |
| 말투가 맞지 않음 | 독자와 예시 부족 | 대상·좋은 예시 |
| 없는 내용 추측 | 정보 부족 처리 규칙 없음 | 중단 조건·확인 필요 표시 |
| 결과가 너무 김 | 우선순위가 없음 | 분량·생략 기준 |
| 숫자가 틀림 | 원문 대조 단계 없음 | 검증 절차 |
| 매번 입력이 다름 | 입력 양식 없음 | 입력 템플릿 |

## 한 번에 한 요소만 바꾸세요

목적, 맥락, 조건, 형식, 예시를 모두 동시에 바꾸면 무엇이 효과가 있었는지 알기 어렵습니다.

```text
버전 1 문제: 위험 항목이 본문에 묻힘
바꾼 요소: 결과 형식만 변경
버전 2 변경: 위험과 지원 요청을 맨 위의 별도 표로 배치
나머지 요청과 입력은 동일하게 유지
```

## 같은 입력으로 비교하세요

요청을 비교할 때는 같은 입력 자료를 사용합니다. 입력까지 달라지면 결과 차이가 프롬프트 때문인지 자료 때문인지 알 수 없습니다.

## 정상·누락·예외 사례를 시험하세요

### 정상 사례

필수 정보가 모두 있는 평범한 자료입니다. 원하는 결과가 나오는지 확인합니다.

### 누락 사례

날짜나 담당자 하나를 뺍니다. 빈칸을 만들어내지 않고 질문하거나 표시하는지 확인합니다.

### 예외 사례

서로 다른 수치나 중복 담당자를 넣습니다. 충돌을 숨기지 않고 작업을 멈추는지 확인합니다.

## ChatGPT에게 평가를 도와달라고 하세요

```text
아래 요청, 입력, 결과를 평가 기준표에 따라 검토해줘.
각 항목을 통과·수정 필요로 표시하고 근거를 적어줘.
가장 영향이 큰 문제 하나와 요청에서 바꿀 요소 하나만 추천해줘.
결과를 직접 수정하지 말고 내가 비교할 수 있게 평가만 해줘.
```

자기 평가는 참고용입니다. 정확성과 안전성은 원문과 사람이 다시 확인합니다.

## 개선 기록표

| 버전 | 바꾼 요소 | 바꾼 이유 | 결과 변화 | 부작용 | 유지 여부 |
|---|---|---|---|---|---|
| 1.0 | 최초 템플릿 | 기준선 | 누락 2건 | 없음 | 수정 |
| 1.1 | 검증 규칙 | 날짜 누락 방지 | 누락 0건 | 결과가 길어짐 | 유지 |
| 1.2 | 출력 형식 | 검토 시간 단축 | 5분 단축 | 없음 | 유지 |

좋아진 점만 아니라 새로 생긴 문제도 기록합니다.

## 언제 개선을 멈출까요?

- 중요한 오류가 통과 기준 안에 들어왔다.
- 정상·누락·예외 사례를 모두 처리한다.
- 사람이 수정하는 시간이 충분히 줄었다.
- 더 복잡한 요청이 주는 이득보다 관리 부담이 커졌다.

완벽한 프롬프트보다 안정적으로 다시 쓸 수 있는 프롬프트가 좋습니다.

## 직접 해보기

### 산출물

- 첫 요청과 첫 결과
- 평가 기준표
- 한 요소만 바꾼 개선 버전
- 같은 입력으로 비교한 기록
- 정상·누락·예외 시험 결과

### 완료 체크

- [ ] 실행 전에 평가 기준과 통과 조건을 정했다.
- [ ] 첫 버전과 걸린 시간을 보관했다.
- [ ] 실패를 원인별로 나눴다.
- [ ] 한 번에 한 요소만 바꿨다.
- [ ] 같은 입력으로 전후 결과를 비교했다.
- [ ] 정상·누락·예외 사례를 시험했다.
- [ ] 부작용과 다음 개선점을 기록했다.

## 기억할 한 문장

**좋은 프롬프트는 한 번에 떠오르는 문장이 아니라 같은 기준으로 시험하고 고친 기록에서 만들어집니다.**
