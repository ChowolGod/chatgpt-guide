# 하나의 업무 흐름을 ChatGPT와 함께 설계하기

> 상태: 초안

## 최종 DIY 프로젝트

앞에서 고른 업무와 개선한 요청 템플릿을 하나의 반복 가능한 업무 흐름으로 연결합니다. 목표는 버튼 하나로 모든 일을 끝내는 것이 아니라, **다른 날에도 안전하게 다시 실행할 수 있는 절차**를 만드는 것입니다.

## 최종 산출물

- 업무 흐름 한 장 요약
- 단계별 요청 템플릿
- 입력 자료 체크리스트
- 결과 검증·승인 체크리스트
- 두 번의 실행 기록과 다음 개선점

## 1단계: 시작과 끝을 정의하세요

```text
업무 이름: 주간 고객 의견 요약
시작 조건: 매주 금요일, 승인된 문의 자료가 준비됨
시작 자료: 일주일간 고객 문의 내역
최종 산출물: 팀 회의용 1쪽 요약
완료 조건: 주요 주제, 빈도, 대표 사례, 다음 행동이 검토됨
사용자: 고객지원 팀장
```

“분석하기”처럼 끝이 보이지 않는 말보다 누가 어떤 결과를 받아 무엇을 할지 적습니다.

## 2단계: 작은 결과로 나누세요

```text
자료 확인
→ 개인정보 제거
→ 문의 분류
→ 빈도와 대표 사례 검토
→ 1쪽 보고서 초안
→ 담당자 승인
→ 팀 공유
```

각 단계가 끝났는지 확인할 수 있는 산출물이 있어야 합니다. 문제가 생기면 어느 단계로 돌아갈지도 정합니다.

## 3단계: 역할을 구분하세요

| 단계 | ChatGPT가 도울 일 | 사람이 할 일 |
|---|---|---|
| 자료 준비 | 필요한 열 목록 제안 | 사용 권한·최신본 확인 |
| 정보 보호 | 의심되는 민감정보 표시 | 삭제·사용 여부 결정 |
| 분류 | 같은 기준으로 초안 분류 | 애매한 사례 판단 |
| 요약 | 표와 문서 초안 작성 | 숫자·인용 원문 대조 |
| 승인 | 확인 목록 정리 | 최종 승인과 책임 |
| 공유 | 메시지 초안 작성 | 수신자 확인 후 발송 |

판단과 책임까지 넘기지 말고, 반복과 초안 작성에 집중합니다.

## 4단계: 업무 흐름 한 장을 작성하세요

```text
[업무 이름]

[목적과 사용자]

[시작 조건]

[입력 자료]
- 필수 자료:
- 최신본 기준:
- 제외할 민감정보:

[단계]
1. 입력 확인 — 결과: ______ — 검토자: ______
2. 자료 정리 — 결과: ______ — 검토자: ______
3. 초안 작성 — 결과: ______ — 검토자: ______
4. 사실 검증 — 결과: ______ — 검토자: ______
5. 승인·공유 — 결과: ______ — 승인자: ______

[중단 조건]

[완료 기준]

[기록 위치와 템플릿 버전]
```

## 5단계: 단계별 요청을 연결하세요

한 번에 최종 결과를 요청하기보다 중간 결과를 검토한 뒤 다음 단계로 갑니다.

### 요청 1: 입력 확인

```text
아직 분석하지 말고 입력 자료가 준비됐는지 확인해줘.
필수 열, 기간, 빈 값, 중복, 민감정보 의심 항목을 알려줘.
문제가 있으면 다음 단계로 넘어가지 마.
```

### 요청 2: 정리와 분류

```text
승인된 자료만 사용해 정해진 분류 기준으로 정리해줘.
애매한 항목은 임의로 넣지 말고 별도 목록으로 남겨줘.
각 결과가 어느 원문 행에서 왔는지 표시해줘.
```

### 요청 3: 최종 초안

```text
검토가 끝난 분류표를 바탕으로 1쪽 보고서 초안을 작성해줘.
새로운 사실은 추가하지 말고,
주요 주제, 빈도, 대표 사례, 다음 행동 순서로 정리해줘.
확인하지 못한 내용은 본문과 분리해줘.
```

## 6단계: 중단·승인·복구 지점을 표시하세요

### 중단 조건

- 필수 입력이 없거나 서로 충돌한다.
- 개인정보와 기밀정보를 안전하게 제거할 수 없다.
- 원문 근거를 찾을 수 없다.
- 승인된 범위를 넘는 접근이나 행동이 필요하다.

### 승인 지점

- 중요한 수치와 인용을 사용하기 전
- 외부 수신자에게 보내기 전
- 파일을 공유·게시·수정·삭제하기 전
- 비용이나 사람의 권리에 영향을 주는 결정 전

### 복구 방법

- 원본은 바꾸지 않고 복사본에서 작업한다.
- 중간 산출물과 버전을 남긴다.
- 실패하면 마지막으로 승인된 단계부터 다시 시작한다.

## 7단계: 첫 번째 실행

실제 자료나 민감정보를 제거한 현실적인 자료로 처음부터 끝까지 실행합니다.

```text
실행 날짜:
템플릿 버전:
입력 준비 시간:
전체 소요 시간:
멈춘 단계:
발견한 오류:
사람이 수정한 내용:
완료 기준 통과 여부:
```

성공 여부만 적지 말고 사람의 수정 시간도 기록하세요.

## 8단계: 회고하고 하나만 고치세요

```text
계속 유지할 것:
가장 큰 문제:
문제가 생긴 단계:
다음 버전에서 바꿀 요소 하나:
예상되는 부작용:
```

문제가 프롬프트가 아니라 입력 양식, 승인 지연, 최신 자료 위치에 있을 수도 있습니다. 업무 흐름 전체에서 원인을 찾으세요.

## 9단계: 두 번째 실행

다른 날짜나 다른 사례로 다시 실행합니다. 한 번 성공한 것은 재사용 가능성을 증명하지 못합니다.

| 비교 항목 | 첫 실행 | 두 번째 실행 |
|---|---:|---:|
| 전체 시간 |  |  |
| 사람의 수정 시간 |  |  |
| 중요 오류 |  |  |
| 누락 항목 |  |  |
| 완료 기준 통과 |  |  |

## 10단계: 운영 여부를 결정하세요

- **그대로 사용:** 목표를 충족하고 위험이 통제된다.
- **수정 후 재시험:** 가치가 있지만 오류나 예외가 남았다.
- **범위 축소:** 일부 단계만 안정적이다.
- **사용 중단:** 검토 비용이나 위험이 절감 효과보다 크다.

사용하지 않기로 한 결정도 좋은 실험 결과입니다.

## 다른 사람에게 넘길 수 있는지 확인하세요

동료가 다음 질문 없이 실행할 수 있는지 살펴봅니다.

- 언제 시작하는가?
- 어느 자료의 어떤 버전을 쓰는가?
- 어떤 빈칸을 채우는가?
- 어디서 멈추고 누구에게 묻는가?
- 무엇을 확인해야 완료되는가?
- 결과와 실행 기록을 어디에 저장하는가?

## 최종 완료 체크

- [ ] 실제 내 업무에 적용했다.
- [ ] 시작 자료, 사용자, 최종 산출물, 완료 기준을 정했다.
- [ ] 업무를 검토 가능한 작은 단계로 나눴다.
- [ ] ChatGPT의 보조 작업과 사람의 판단을 구분했다.
- [ ] 정보가 없거나 충돌할 때의 중단 조건을 정했다.
- [ ] 오류·개인정보·권한·승인 위험을 검토했다.
- [ ] 외부 행동 전에 사람의 승인 지점을 두었다.
- [ ] 두 번 실행하고 시간·오류·수정 내용을 비교했다.
- [ ] 다른 날에도 사용할 템플릿과 기록을 남겼다.
- [ ] 사용·수정·축소·중단 중 다음 결정을 내렸다.

## 가이드를 마치며

이제 좋은 프롬프트를 외울 필요는 없습니다. 할 일을 작은 단계로 설명하고, 필요한 자료와 조건을 주고, 결과를 검토해 다음 요청으로 고칠 수 있습니다. 무엇보다 ChatGPT가 할 일과 사람이 책임질 일을 구분해 자신의 업무 방식을 설계할 수 있습니다.

```text
일단 요청한다
→ 결과를 확인한다
→ 부족한 조건을 더한다
→ 중요한 사실을 검증한다
→ 실제 산출물로 연결한다
→ 다음번을 위해 절차를 남긴다
```

작은 업무 하나에서 시작하세요. 실제로 써보고 고친 기록이 곧 나만의 ChatGPT 활용법입니다.
