# 반복되는 요청 템플릿 만들기

> 상태: 초안

## 이번 장에서 할 일

매번 유지할 지시와 바뀌는 입력을 분리해 복사·수정할 수 있는 개인 업무 템플릿을 만듭니다.

## 템플릿은 완성된 주문서입니다

프롬프트 문구만 저장하면 다음번에 어떤 자료를 넣고 무엇을 확인했는지 잊기 쉽습니다. 다음 여섯 요소를 한 묶음으로 남기세요.

```text
목적 → 입력 → 대상 → 조건 → 결과 형태 → 검증
```

## 1. 목적

무엇을 만들지가 아니라 왜 만드는지를 씁니다.

```text
주간 업무 상황을 팀장이 2분 안에 파악하고
지원이 필요한 일을 결정할 수 있게 한다.
```

목적이 있으면 무엇을 줄이고 강조할지 판단하기 쉽습니다.

## 2. 입력

필요한 자료와 범위를 적습니다.

```text
입력 자료: 지난주 업무 메모
필수 항목: 업무명, 상태, 날짜, 담당자
제외 정보: 고객 실명과 연락처
정보가 없을 때: 추측하지 않고 [확인 필요] 표시
```

## 3. 대상

결과를 읽을 사람의 배경과 필요한 행동을 씁니다.

```text
독자: 세부 진행을 모르는 팀장
읽은 뒤 할 일: 지연 업무의 지원 여부 결정
```

## 4. 조건과 우선순위

조건이 충돌할 때 무엇이 더 중요한지 정합니다.

```text
- 정확성이 짧은 분량보다 우선
- 완료, 진행 중, 위험, 지원 요청 순서
- 전체 500자 이내를 목표로 하되 필수 위험은 생략하지 않음
- 입력에 없는 날짜와 수치는 만들지 않음
```

## 5. 결과 형태

최종 결과의 구조를 보여줍니다.

```text
제목: 주간 업무 현황 — YYYY-MM-DD

1. 완료
2. 진행 중
3. 위험
4. 필요한 지원

마지막: 확인 필요 항목 목록
```

## 6. 검증

결과를 내기 전에 무엇을 확인해야 하는지 지정합니다.

```text
초안을 만든 뒤 입력과 다시 대조해
빠진 업무, 바뀐 날짜·수치·담당자를 확인해줘.
확인 결과를 본문과 분리해 보여줘.
```

## 완성 템플릿

```text
[목적]
{{이 결과를 사용하는 이유}}

[입력]
{{자료를 붙여넣거나 첨부 파일 설명}}

[대상]
{{읽는 사람과 읽은 뒤 할 행동}}

[할 일]
{{자료를 어떻게 처리할지}}

[조건과 우선순위]
- {{반드시 지킬 조건}}
- {{조건이 충돌할 때 우선할 것}}
- 없는 정보는 추측하지 말고 [확인 필요]로 표시

[결과 형태]
{{제목, 항목 순서, 분량, 표 구조}}

[검증]
- 중요한 이름, 날짜, 수치, 인용을 원문과 대조
- 빠진 내용과 사용한 가정을 별도 목록으로 표시
- 외부 발송이나 변경은 하지 않고 초안만 제시
```

## 빈칸은 쉽게 알아보게 만드세요

`{{보고 기간}}`, `{{대상}}`처럼 매번 바꿀 부분에 같은 표시를 사용합니다. 빈칸이 남아 있으면 실행 전에 질문하도록 요청합니다.

```text
중괄호로 표시된 항목이 비어 있으면 작업을 시작하지 말고
필요한 질문만 먼저 해줘.
```

## 좋은 예시 하나를 함께 보관하세요

원하는 결과의 구조와 말투가 중요한 경우 민감정보를 제거한 좋은 예시를 붙입니다. 예시의 내용까지 복사하지 말고 형식과 스타일만 참고하라고 설명하세요.

## 템플릿 사용 설명서

다른 날의 나와 동료도 쓸 수 있도록 다음을 적습니다.

- 언제 사용하는가
- 언제 사용하지 않는가
- 준비할 자료
- 바꿀 빈칸
- 최종 검토자
- 결과 저장 위치
- 버전과 마지막 수정일

## 어디까지 믿어야 할까요?

긴 템플릿도 정확성을 보장하지 않습니다. 매번 바뀌는 날짜·수치·이름, 새 규정, 예외 상황은 실행할 때 다시 확인합니다. 템플릿이 오래됐다면 먼저 업무 절차가 바뀌지 않았는지 검토하세요.

## 직접 해보기

### 산출물

- 여섯 요소가 들어간 요청 템플릿
- 안전하게 바꾼 입력 예시
- 원하는 결과 예시
- 사용 설명서와 검토자

### 완료 체크

- [ ] 목적과 독자를 구분해 적었다.
- [ ] 입력의 필수 항목과 제외 정보를 정했다.
- [ ] 조건의 우선순위를 적었다.
- [ ] 결과의 항목과 순서를 지정했다.
- [ ] 모르는 정보를 추측하지 않도록 했다.
- [ ] 원문 대조와 외부 행동 제한을 넣었다.
- [ ] 빈칸, 버전, 수정일, 사용 설명서를 남겼다.

## 기억할 한 문장

**다시 쓸 수 있는 요청은 멋진 문장 하나가 아니라 목적부터 검증까지 채울 수 있는 양식입니다.**
