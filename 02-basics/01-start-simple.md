# 일단 요청해보기

> 상태: 초안

## 이번 장에서 할 일

완벽한 프롬프트를 만들려는 부담을 내려놓고, **해야 할 일과 원하는 결과**만으로 첫 대화를 시작합니다.

## 프롬프트는 시험 문제가 아닙니다

프롬프트는 ChatGPT에게 보내는 질문이나 요청입니다. 정해진 주문이나 반드시 지켜야 할 공식은 없습니다. 우리가 평소에 동료에게 말하듯 시작할 수 있습니다.

```text
회의 안내 이메일을 작성해줘.
```

이 정도로도 첫 결과를 받을 수 있습니다. 결과가 부족하면 그때 필요한 정보를 더하면 됩니다.

처음부터 역할, 배경, 형식, 예시, 주의사항을 모두 넣으려고 하면 오히려 시작하지 못할 수 있습니다. **짧게 요청하고 결과를 관찰하는 것**도 좋은 방법입니다.

## 첫 요청에 필요한 최소 두 가지

### 1. 할 일

ChatGPT가 무엇을 해야 하는지 동사로 말합니다.

- 작성해줘
- 요약해줘
- 분류해줘
- 비교해줘
- 설명해줘
- 아이디어를 제안해줘
- 체크리스트로 바꿔줘

### 2. 결과물

무엇을 만들어야 하는지 말합니다.

- 이메일
- 회의록
- 요약
- 비교표
- 보고서 개요
- 발표 순서
- 할 일 목록

둘을 합치면 첫 요청이 됩니다.

```text
회의 메모를 요약해줘.
```

```text
고객 의견을 주제별로 분류해줘.
```

```text
신입사원 교육 체크리스트를 만들어줘.
```

## 모르는 것이 많을 때 시작하는 법

원하는 결과가 아직 분명하지 않아도 시작할 수 있습니다.

### 선택지를 요청하기

```text
분기 회의를 준비하고 있어. 어떤 산출물이 필요할지 제안해줘.
```

### 질문을 요청하기

```text
고객 행사를 기획하려고 해.
좋은 기획안을 만들기 위해 내가 먼저 답해야 할 질문을 해줘.
```

### 생각을 정리해달라고 하기

```text
아래는 새 교육 과정에 대한 뒤섞인 메모야.
비슷한 내용을 묶고, 아직 결정되지 않은 항목을 찾아줘.
```

## 이번 Part에서 발전시킬 예시

PART 2에서는 하나의 요청을 장마다 조금씩 발전시킵니다.

첫 요청은 아주 짧습니다.

```text
회의 안내 이메일을 작성해줘.
```

이 요청으로 답을 받은 뒤 다음을 살펴봅니다.

- 누구에게 보내는 이메일인지 드러나는가?
- 왜 회의를 하는지 알 수 있는가?
- 날짜, 시간, 장소가 있는가?
- 참석자가 무엇을 해야 하는지 분명한가?
- 실제로 복사해 보낼 수 있는 형태인가?

부족한 점이 보이면 실패한 것이 아닙니다. 다음 요청에 넣을 단서를 찾은 것입니다.

## 결과를 읽는 세 가지 질문

첫 결과를 받으면 바로 다시 쓰게 하기보다 먼저 진단합니다.

1. **맞는가?** 내가 말한 사실과 다르거나 새로 지어낸 내용은 없는가?
2. **쓸 만한가?** 실제 목적과 독자에게 맞는가?
3. **빠진 것은 무엇인가?** 사용하려면 어떤 정보나 조건이 더 필요한가?

예를 들어 날짜를 알려주지 않았는데 특정 날짜가 들어갔다면, 다음처럼 말합니다.

```text
날짜와 장소는 내가 아직 알려주지 않았어.
추측해서 채우지 말고 빈칸으로 남겨줘.
```

## 자주 생기는 막힘

### “무슨 말을 해야 할지 모르겠어요”

완성할 일을 말하고 질문을 요청하세요.

```text
주간 보고서를 만들어야 해.
좋은 보고서를 만들기 위해 필요한 정보를 한 번에 5개 이내로 질문해줘.
```

### “요청이 너무 짧은 것 같아요”

짧아도 괜찮습니다. 첫 결과에서 부족한 점을 찾는 것이 이번 연습의 목적입니다.

### “첫 결과가 마음에 들지 않아요”

새 대화를 시작하기 전에 같은 대화에서 무엇이 아쉬운지 말해보세요.

```text
너무 딱딱해. 팀원에게 보내는 자연스러운 말투로 바꿔줘.
```

## 직접 해보기

### 과제

오늘 해야 할 일 중 하나를 골라 `할 일 + 결과물` 형태로 첫 요청을 만듭니다.

```text
[자료 또는 주제]를 [원하는 결과물]로 [할 일]해줘.
```

예시:

```text
아래 업무 메모를 할 일 목록으로 정리해줘.
```

결과를 받은 뒤 맞는 점, 아쉬운 점, 빠진 점을 각각 하나씩 적습니다.

### 완료 체크

- [ ] 할 일과 결과물을 넣어 첫 요청을 보냈다.
- [ ] 첫 결과를 완성품이 아닌 초안으로 읽었다.
- [ ] 맞는 점, 아쉬운 점, 빠진 점을 찾았다.
- [ ] 다음 요청에 추가할 내용을 하나 정했다.

## 기억할 한 문장

> 첫 요청은 출발점입니다. 짧게 시작하고 결과를 보며 필요한 정보를 더하면 됩니다.
