# 결과 형태를 지정하기

> 상태: 초안

## 이번 장에서 할 일

결과를 어디에 사용할지 생각하고 **이메일, 표, 목록, 보고서처럼 바로 쓸 수 있는 형태**를 요청합니다.

## 내용이 같아도 형태는 달라집니다

같은 회의 정보라도 사용처에 따라 필요한 결과가 다릅니다.

### 이메일

```text
제목과 본문이 있는 이메일 형식으로 작성해줘.
```

### 메신저 공지

```text
모바일 화면에서 빠르게 읽을 수 있는 메신저 공지로 바꿔줘.
첫 줄에 회의 일시를 쓰고, 준비물은 글머리표로 보여줘.
```

### 일정 등록용 요약

```text
캘린더에 옮길 수 있게 제목, 일시, 참석자, 장소, 설명으로 구분해줘.
```

좋은 결과 형태는 꾸미기 위한 장식이 아니라 **다음 업무를 줄이는 방법**입니다.

## 결과 형태를 정하는 네 가지 질문

1. 어디에 붙여 넣거나 저장할 것인가?
2. 누가 얼마나 빨리 읽어야 하는가?
3. 무엇을 찾아야 하는가?
4. 결과를 받은 뒤 어떤 행동을 할 것인가?

예를 들어 회의 후 담당자와 마감일을 확인해야 한다면 문단보다 표가 적합합니다.

| 할 일 | 담당자 | 마감일 | 상태 |
|---|---|---|---|
| 고객 확인 질문 정리 | 확인 필요 | 10월 12일 | 미정 |

담당자가 정해지지 않았다면 빈칸을 임의로 채우지 않고 `확인 필요`라고 표시하게 합니다.

## 자주 쓰는 결과 형태

### 목록

빠르게 훑고 순서를 확인할 때 좋습니다.

```text
해야 할 일을 실행 순서대로 번호 목록으로 정리해줘.
각 항목은 동사로 시작해줘.
```

### 표

같은 기준으로 여러 항목을 비교할 때 좋습니다.

```text
세 업체를 가격, 일정, 지원 범위, 확인할 질문의 열로 비교해줘.
정보가 없는 칸은 “제공되지 않음”으로 표시해줘.
```

### 요약 + 상세

먼저 결론을 보고 필요할 때 근거를 읽게 할 수 있습니다.

```text
맨 위에 3줄 핵심 요약을 쓰고, 그 아래에 근거와 세부 내용을 설명해줘.
```

### 체크리스트

누락 없이 실행하거나 검토할 때 좋습니다.

```text
행사 전날 확인할 내용을 체크박스가 있는 목록으로 만들어줘.
준비, 참석자, 장소, 장비, 비상 대응으로 나눠줘.
```

### 정해진 문서 구조

조직의 양식이 있다면 제목만 알려주기보다 구조를 제공합니다.

```text
다음 순서의 1쪽 보고서로 작성해줘.
1. 결론
2. 현재 상황
3. 근거 수치
4. 위험과 대응
5. 필요한 결정
```

## 표가 항상 좋은 것은 아닙니다

표는 비교에는 유용하지만 긴 설명이나 미묘한 관계를 담기 어렵습니다.

| 목적 | 어울리는 형태 |
|---|---|
| 빠른 비교 | 표 |
| 실행 순서 | 번호 목록 |
| 설득과 맥락 설명 | 짧은 문단 |
| 누락 방지 | 체크리스트 |
| 전달과 회신 요청 | 이메일 또는 메시지 |
| 결정 지원 | 핵심 요약 + 근거 + 선택지 |

어떤 형태가 좋은지 모르겠다면 제안받을 수 있습니다.

```text
이 결과를 팀장이 2분 안에 검토하고 승인 여부를 결정해야 해.
가장 적합한 결과 형식을 먼저 제안하고, 그 형식으로 작성해줘.
```

## 회의 안내 요청에 형식 더하기

지금까지의 내용을 하나로 합치면 다음과 같습니다.

```text
프로젝트에 참여하는 외부 고객에게 보낼 중간 점검 회의 안내 이메일을 작성해줘.
지난 회의에서 일정 지연 가능성을 공유했고, 이번 회의에서는 변경 일정을 확정해야 해.

형식:
- 제목 1개
- 인사말
- 회의 목적 2문장 이내
- 일시, 장소, 준비할 내용을 글머리표로 정리
- 10월 10일까지 참석 가능 여부를 요청하는 마무리

장소와 링크는 정해지지 않았으니 “확인 필요”로 표시해줘.
본문은 7문장 이내로 작성해줘.
```

## 다음 산출물까지 연결하기

하나의 내용을 여러 형식으로 바꾸면 실제 업무 흐름이 됩니다.

```text
이 이메일을 바탕으로 다음 두 가지도 만들어줘.
1. 사내 메신저에 올릴 3문장 요약
2. 캘린더에 입력할 제목과 설명
세 결과의 날짜와 시간은 반드시 같아야 해.
```

형식을 바꿀 때 사실이 달라지지 않았는지 확인합니다.

## 직접 해보기

### 과제

같은 내용을 서로 다른 두 가지 형태로 요청합니다.

- 한 사람에게 전달할 이메일 또는 메시지
- 여러 항목을 한눈에 확인할 표 또는 체크리스트

두 결과를 비교해 어느 형태가 어떤 상황에 더 유용한지 적습니다.

### 완료 체크

- [ ] 결과를 사용할 장소와 독자를 생각했다.
- [ ] 목적에 맞는 형태를 골랐다.
- [ ] 표의 열이나 문서의 순서를 구체적으로 말했다.
- [ ] 형식을 바꾸는 동안 사실이 달라지지 않았는지 확인했다.
